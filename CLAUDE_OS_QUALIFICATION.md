# Claude for Open Source Program — Qualification Statement

**Repository:** asr-eval-toolkit (https://github.com/veyhthan/asr-eval-toolkit)

I am the primary maintainer and sole author of `asr-eval-toolkit`, an open-source Python toolkit for scoring ASR transcripts and auditing annotation quality. Most evaluation tooling stops at WER/CER — catching annotation problems that silently poison training data, like filler tags (`[uh]`, `[um]`), timestamp drift, and speaker-boundary inconsistencies, usually means writing a custom script nobody maintains three months later. This project fills that gap: reusable, auditable, zero-dependency.

It is built for researchers and small teams who need reproducible evaluation without a closed lab platform. It computes word and character error rate via edit distance with per-utterance detail, detects and counts filler tags, and outputs markdown plus JSON. Zero runtime dependencies — Python standard library only, runs on Python 3.8+. The code is small enough to read in ten minutes, fully type-hinted, and tested.

I am a medical student (MBBS, KMC Medical College, graduating 2029) with a research background in ASR evaluation, including work on Project Seal through Handshake AI and Mercor. My work sits at the intersection of clinical research and speech technology: I evaluate ASR systems on medical and spoken-language transcripts where annotation quality directly affects whether a model learns from clean signal or from transcripts with undetected filler tags, gaps, and boundary errors. I built this toolkit because existing options did not fit — paid platforms are opaque and subscription-locked, generic libraries like jiwer give you WER/CER but ignore annotation quality, and writing a custom script each time is not reproducible.

The project is real, released software. It has a proper Python package structure (installable via `pip install asr-eval-toolkit`), a CLI entry point (`asr-eval`), a 34-test suite with 68% coverage and 100% coverage on the core scoring module, CI that runs lint, type checking, and the full test suite across Python 3.8–3.12, a GitHub Actions release workflow that auto-publishes to PyPI, a CHANGELOG, a CITATION.cff file, a code of conduct, a security policy, issue and PR templates, and full usage and API documentation. The repo carries 10 relevant GitHub topics and was first released as v0.1.0 on August 12, 2026. Ruff is clean.

I maintain the project personally and actively. Every change is tested and linted before it lands, and documentation stays in sync with the code. The scope is intentionally narrow and dependency-free, keeping it auditable and long-lived.

If awarded the subscription, I would use Claude Max to accelerate three concrete areas: (1) expanding the scoring toolkit with additional metrics, TSV/CSV export, and per-utterance detail; (2) improving annotation-quality detection — timestamp checking and speaker-boundary flagging — which are on the roadmap and directly tied to my research workflow; and (3) growing documentation and examples so the toolkit reaches researchers who are not ASR specialists. The subscription would also support my broader open-source work, including a 477-skill collection and curated Anthropic agent skill ports.

`asr-eval-toolkit` is the project I am best positioned to maintain and grow. It addresses a real, specific problem, is transparent by design, and serves a researcher audience that benefits directly from high-quality, auditable evaluation tooling. I am committed to keeping it active, documented, and useful.
